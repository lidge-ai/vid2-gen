Extend `src/assets/ima2.test.ts`, `src/assets/resolve.test.ts`, `src/assets/manifest.test.ts`, `src/assets/cli.test.ts`, `tests/e2e/assets-ima2.test.ts`, and `tests/e2e/examples.test.ts`; assert invalid requests make zero provider calls, missing capability makes zero paid calls, seed/reference bytes change hash, exact hold warning count/frames, and offline proxy render + QA/analyze. **Assumptions:** upstream model and mode limits may change; refresh the ima2/xAI contract at implementation time. A live generation receipt needs an available account and explicit provider authorization; if unavailable, WP5 is not fully verified and the offline CI fixture cannot substitute for it.

## Risks

1. Changing cumulative frame placement can shift existing timeline cuts by several frames; compare golden plans and full renders, and call out the v1 behavioral correction in release notes.
2. Pretrim can consume disk and change seek/VFR behavior; lossless intermediates still need frame-level equivalence proof and bounded cleanup.
3. Camera simplification may drop a brief target or still exceed ffmpeg parser capacity; measure pixel framing and expression bytes, fail before ffmpeg if unsafe.
4. Scene detection and onset alignment are estimates; silent/ambiguous music, dissolves and rapid flashes need method/uncertainty labels.
5. Vision findings can be wrong or miss unsampled motion/audio; schema validation proves shape and provenance, not the critic's accuracy. Sending frames to a configured endpoint is an external disclosure and must be explicit.
6. Look filters may vary by ffmpeg build and alter real UI colors/text contrast; capability probe, deterministic seeds, neutral `strength=0`, and final QA are required.
7. A film-long HUD stage render can dominate memory/time; benchmark a representative long timeline and add a bounded fallback if needed.
8. ima2/xAI video limits and account capabilities drift; no billed request should be made from stale assumptions or an unverified mode.
