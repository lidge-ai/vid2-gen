1. **Hold fix changes every auto-camera render.** Item 5 treats the string-hold bug as authored strings being ignored. The schema default is itself a string: `hold: TimeLiteral.default("0.8s")` (`src/timeline/schema.ts:44`). So `typeof cam.hold === "number"` (`src/capture/decorate.ts:47-48`) is false for every default camera, and today's renders all use planCamera's own defaults, hold 0.5 s and merge 0.7 s (`src/capture/camera.ts:60,89`). After the fix, every `{auto:"events"}` layer moves to hold 0.8 s and merge 0.8 s. Put this in the CHANGELOG behavior-change entry next to cumulative rounding. Add a `src/capture/decorate.test.ts` activation case with default hold "0.8s" and with "2b" beside a beat grid, asserting `planCamera` receives 0.8 s and 2 beats in seconds. The item 5 tests do not cover the decorate fix, and `decorate.test.ts` exists. `hold` in beat units must parse with `t.beat` from the resolved timeline.
2. **Camera error has no timeline path.** Item 5 names source id and scene id. D2.4 asked for a path `scenes.i.layers.j.camera`. `decorateCaptureLayers` knows the scene and layer positions, so throw with `details.path`. The error surfaces from `vid2 resolve` and render/compile (`src/cli/commands/resolve.ts:20`, `src/cli/commands/plan-shared.ts:36`) but not from `vid2 validate`. Document that limit in structure/capture.md.

The cut must also keep source `pix_fmt` and color range tags, because `scale=in_range=auto` depends on the range (`src/compile/layers/media.ts:66`). Add that to the pretrim test.
