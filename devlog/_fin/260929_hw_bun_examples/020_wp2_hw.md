# 020 WP2 results: hardware encode modes

`vid2 render --hw-accel disable|if-possible|required` (`--hw` stays as shorthand for `if-possible`) and `--hw-encoder <family>` choose the final
encoder once, before segments render. Every candidate must pass a five-frame 256×144 trial encode; probes are cached per process.
H.264/HEVC cover videotoolbox, nvenc, qsv, amf and vaapi; ProRes uses prores_videotoolbox. VAAPI opens its device before the inputs and
appends `format=nv12,hwupload` to the post chain. Render JSON, the result object and `<out>.render.json` report `encoder: { name, hardware }`.
`vid2 doctor --hw` lists which compiled-in encoders pass the probe. The design follows Remotion's three modes (001_research.md).

## Calibration (M5 Pro, ffmpeg 9.0.2; reference = software final render of opus-astra-paper, 1080p30, 759 frames, grain + vignette)

| Encoder | Setting | Size | VMAF |
|---|---|---|---|
| h264_videotoolbox | q:v 65 (0.3 default) | 4.2 MB | 96.6 |
| h264_videotoolbox | **q:v 70 (new default)** | 13.8 MB | 97.4 |
| h264_videotoolbox | q:v 72 / 78 / 84 | 23 / 66 / 145 MB | 97.6 / 97.9 / 98.0 |
| hevc_videotoolbox | q:v 60 / 70 | 1.9 / 4.8 MB | 95.2 / 97.0 |
| hevc_videotoolbox | **q:v 74 (new default)** | 8.7 MB | 97.7 |
| libx264 slow crf 18 (re-encode) | software parity point | 49.3 MB | 97.5 |

End to end: `vid2 render timeline.json --hw-accel required` took 34.3 s (software 69.6 s), 22.2 MB (software 65.3 MB), VMAF 97.1 against the
software render. NVENC, QSV, AMF and VAAPI settings follow vendor guidance and are unmeasured on real hardware; CI covers their argument
construction with a fake runner, and every host runs the real render test, which takes the hardware or fallback branch depending on what probes.
