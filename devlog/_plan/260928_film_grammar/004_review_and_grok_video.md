# Reviewing agent-made video and generating Grok clips

Research checked on 2026-09-28. Repository observations are pinned to vid2-gen commit [`13a0e45`](https://github.com/lidge-ai/vid2-gen/tree/13a0e45a067c009f08c071caa7acd56eec2f7c7e) and ima2-gen commit [`0b9c2c9`](https://github.com/lidge-ai/ima2-gen/tree/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0). Provider limits and prices are current documentation, not a guarantee for a particular account.

## Part 1 — Multimodal video review

An agent without direct sight or hearing can still review a render by requesting a **time-indexed evidence package**: sampled frames, short motion strips, machine measurements, and audio visualizations or transcription. A vision-capable model then critiques that package against the timeline and an explicit rubric. A native-video model can examine the MP4 directly, but its sampling policy still matters: a one-frame flash between sampled seconds can disappear. Gemini explicitly warns that its default 1 FPS static sampling can miss fast action. [Gemini video understanding](https://ai.google.dev/gemini-api/docs/video-understanding)

### Current input contracts and budgets

| API | Video or frame input | Relevant limits and cost units |
|---|---|---|
| **Gemini native video** | Upload an MP4 with the Files API and pass `{"type":"video","uri":file.uri,"mime_type":"video/mp4"}` plus a text part to `POST /v1beta/interactions`. Static mode samples at **1 FPS** with timestamps; `processing: {"type":"static","fps":0.5}` changes this to one frame per two seconds, and `start_offset`/`end_offset` clip by seconds. Prompt for specific moments using `MM:SS`. Agentic mode navigates video, transcript, frames and audio on demand. [Upload example](https://ai.google.dev/gemini-api/docs/video-understanding), [clipping and FPS](https://ai.google.dev/gemini-api/docs/video-understanding) | For a **1M-context** model: up to **3 hours** at low media resolution or **1 hour** at high. Static mode uses **66 tokens/frame** at low media resolution or **258 tokens/frame** otherwise, plus **32 audio tokens/second** and metadata: roughly **100 or 300 tokens/second** at 1 FPS. Agentic token use varies. Inline video is **<100 MB**; Files API lists **20 GB paid / 2 GB free**. No separate universal “frames per request” number is stated; duration and context are the practical ceiling. [Technical details](https://ai.google.dev/gemini-api/docs/video-understanding), [input methods](https://ai.google.dev/gemini-api/docs/video-understanding) |
| **xAI Grok vision** | Send timestamp-labeled PNG/JPEG frames as `input_image` parts beside `input_text` to `POST /v1/responses` with a vision model such as `grok-4.7`; image URL or base64 data URI works. This image-understanding contract is an image sequence, not an MP4 playback contract. [xAI image understanding](https://docs.x.ai/developers/model-capabilities/images/understanding) | **20 MiB per image**; documentation says **no fixed image-count limit**, though context, payload and rate limits still apply. Supported formats are JPEG/PNG. No public fixed tokens-per-frame schedule or video-duration ceiling is given for this image-input route; inspect response usage and budget experimentally. [xAI image limits](https://docs.x.ai/developers/model-capabilities/images/understanding) |
| **OpenAI vision** | Pass repeated `input_image` parts (`image_url` or uploaded `file_id`) with `input_text` to Responses, or `image_url` parts with text to Chat Completions. Label each frame with its timestamp and scene ID in adjacent text. This is an image-sequence workflow. [OpenAI Images and vision](https://developers.openai.com/api/docs/guides/images-vision) | **1,500 images/request**, **512 MB total payload**, and per-image/model context limits; PNG/JPEG/WebP/non-animated GIF. Token cost depends on model, image dimensions and `detail`. For `gpt-6-astra` at `detail: high`, a **1024×1024** frame is **1,229 billable image tokens** and a **2048×2048** frame is resized to 1600×1600 for **3,000**. There is no MP4-duration limit for a list of stills; image count, payload and context bound it. [Input limits](https://developers.openai.com/api/docs/guides/images-vision), [token examples](https://developers.openai.com/api/docs/guides/images-vision) |
| **Claude vision** | Send ordered `image` blocks with base64, URL or file source in Messages, alternating with timestamp labels as text. Animated GIFs use only the first frame, so extract video frames yourself. [Claude vision](https://platform.claude.com/docs/en/build-with-claude/vision) | API maximum **100 images/request** for 200k-context models, **600** for other models; **8000×8000 px** and **10 MB base64** per image on the direct API, with a **32 MB** standard request body. More than 20 images invokes stricter per-image dimensions; ≤2000 px on either edge is the documented cross-platform safe choice. Image cost is `ceil(width/28) × ceil(height/28)` visual tokens before resizing; standard models cap at **1,568** visual tokens / 1,568 px long edge, Claude 4.7+ at **4,784** / 2,576 px. Duration is governed by extracted-frame count, not an MP4 limit. [Claude image limits and tokenization](https://platform.claude.com/docs/en/build-with-claude/vision) |

For Gemini, the current **Interactions** example puts `fps`, `start_offset`, and `end_offset` inside the video's `processing` object. The older Generate Content example uses `videoMetadata.fps`; do not mix the two request shapes. [Current Interactions video guide](https://ai.google.dev/gemini-api/docs/video-understanding), [Generate Content video guide](https://ai.google.dev/gemini-api/docs/generate-content/video-understanding)

### A review package the agent can trust

1. **Keep timeline evidence aligned with output time.** Start with `ffprobe` facts, vid2's resolved scene/cut/event times, and its existing `qa.json`. Vid2 already writes a **0.5 FPS** `contact.png`, scene start/mid/end stills, seam stills at ±1 frame, capture-event stills, and `waveform.png`/`spectrogram.png` when audio exists. It checks format, duration, black/frozen spans, A/V length, loudness, silence, text safety and contrast. This gives the reviewer a factual baseline and targeted frames. [vid2 QA contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md), [artifact extraction](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/qa/artifacts.ts)
2. **Sample by edit and by motion.** For every cut, take one frame before and after and a representative middle frame; add frames at text reveals, transition boundaries, cursor/capture events, and generated-clip start/end. Make a contact sheet with visible timestamps and scene IDs. Within a high-motion interval, take a short **8–12 FPS strip** or a few high-difference frames; a sparse sheet alone cannot prove smoothness, direction, or absence of flicker. These rates are proposed review defaults, not provider limits. PySceneDetect's `detect-content`/`detect-adaptive` and `list-scenes save-images` offer cut detection and scene CSV plus start/middle/end images when no authored timeline exists. [PySceneDetect CLI](https://www.scenedetect.com/docs/latest/cli.html), [vid2 artifact extraction](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/qa/artifacts.ts)
3. **Ask bounded, timestamped questions.** Supply intended audience, one-sentence takeaway, shot list, source provenance, and exact duration. Ask the model to score narrative clarity, visual hierarchy, text legibility, continuity, motion/transition quality, audio fit/sync, and technical faults on a **0–4** scale. Require `scene_id`, `time` (for example `00:07.200`), observed evidence, severity, and a specific proposed fix for each finding; allow “cannot determine from sampled frames.” Ask separately whether the *actual* UI capture matches the claimed product behavior. The rubric and scale are a recommended vid2 review contract. Gemini explicitly supports timestamp-focused prompts in `MM:SS`. [Gemini timestamp prompting](https://ai.google.dev/gemini-api/docs/video-understanding), [vid2 capture and QA contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/README.md)
4. **Translate audio into evidence.** Review the existing waveform for abrupt amplitude changes and silence; inspect the spectrogram for misplaced SFX, frequency gaps or bursts. Pair these pictures with loudness/true-peak/silence measurements and a timestamped speech transcript when dialogue matters. These images can show timing and energy, but cannot establish timbre, whether music feels appropriate, or exact spoken words by themselves. Vid2 already generates `showwavespic` and `showspectrumpic` images and runs audio checks; a future reviewer can attach them to the same timestamp rubric. [vid2 QA contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md), [FFmpeg filters](https://ffmpeg.org/ffmpeg-filters.html)
5. **Recheck edited spans and the final render.** Compare the flagged timestamp with `vid2 preview --at`, fix the timeline, regenerate a proxy, and review the changed scene plus its neighboring seams before final QA. Remotion exposes `still --frame` and targeted `render --frames=0,30,90`; HyperFrames exposes timestamped `snapshot`, a contact sheet, `check --json` findings for layout/motion/contrast and a timed browser seek grid. Their useful pattern is deterministic frame addressing plus machine findings plus visual evidence. [vid2 preview contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md), [Remotion stills](https://www.remotion.dev/docs/cli/still), [HyperFrames CLI](https://github.com/heygen-com/hyperframes/blob/main/docs/packages/cli.mdx)

**Review limitation:** first/last-frame analysis is useful for composition continuity but misses the interior of a clip. ima2's `video analyze` currently extracts first and last frames for Grok vision and labels its method `first-last-frame`; treat it as one input to review, not complete video QA. [ima2 CLI](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/commands/video.ts), [ima2 analyze route](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/routes/videoExtended.ts)

## Part 2 — Grok Imagine video generation

### Direct xAI API

`POST https://api.x.ai/v1/videos/generations` with a bearer xAI API key submits a request and returns `{"request_id":"…"}`. Poll `GET https://api.x.ai/v1/videos/{request_id}` until `status` is `done`, `failed`, or `expired`; `done` contains a temporary `video.url` and duration. Download the MP4 promptly. The xAI SDK wraps the polling. [xAI generation and polling](https://docs.x.ai/developers/model-capabilities/video/generation)

```json
{"model":"grok-imagine-video-1.5","prompt":"A paper boat drifts past camera; gentle lateral motion, no dialogue, stable ending frame","duration":5,"aspect_ratio":"16:9","resolution":"720p","generate_audio":false}
```

These are documented generation fields, with **integer duration 1–15 seconds**, aspect ratios **1:1, 16:9, 9:16, 4:3, 3:4, 3:2, 2:3**, resolution **480p (default), 720p, 1080p**, and optional `generate_audio: false` (audio is generated by default). 1080p is supported by `grok-imagine-video-1.5` for text-to-video and image-to-video; reference-to-video is capped at 720p. [xAI configuration](https://docs.x.ai/developers/model-capabilities/video/generation)

For **image-to-video**, add `"image":{"url":"https://…/first-frame.png"}` or a base64 data URI / Files API `file_id`; this image is the opening frame. If `aspect_ratio` is omitted, the image's ratio is used; setting one overrides and may stretch it. `reference_images` instead guides content without pinning the first frame, with **up to 7** images; 1.5 also accepts up to **3 preset voices** via `reference_audios`, up to **4** interior keyframes (`{image,timestamp_s}`), and a `last_frame` pin. [Image-to-video](https://docs.x.ai/developers/model-capabilities/video/image-to-video), [reference-to-video limits](https://docs.x.ai/developers/model-capabilities/video/reference-to-video), [generation modes](https://docs.x.ai/developers/model-capabilities/video/generation)

`POST /v1/videos/edits` and `POST /v1/videos/extensions` are separate classic-model paths. Edits retain source duration (source cap **8.7 seconds**) and output at no more than **720p**. Extension uses `model: "grok-imagine-video"`, a `video` input, and `duration` for the **added segment**; xAI documents **2–15 seconds** input and **2–10 seconds** added (default 6), output capped at 720p. These are different operations from asking vid2 to place two clips on a timeline. [Generation modes and editing](https://docs.x.ai/developers/model-capabilities/video/generation), [extension contract](https://docs.x.ai/developers/model-capabilities/video/extension)

**Pricing and rate limits:** xAI lists `grok-imagine-video-1.5` output at **$0.08/s 480p**, **$0.14/s 720p**, **$0.25/s 1080p**, plus **$0.01 per input image**; a 5-second 720p clip is **$0.70 output** before input charges. Classic `grok-imagine-video` lists **$0.05/s 480p**, **$0.07/s 720p**, **$0.002 per input image**, and **$0.01 per input-video second**. Both model pages list **10 requests/second**, subject to account-specific limits. [1.5 model pricing](https://docs.x.ai/developers/models/grok-imagine-video-1.5), [classic model pricing](https://docs.x.ai/developers/models/grok-imagine-video)

### Local ima2-gen surface

ima2-gen's [README](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/README.md) documents a running local server, explicit Grok OAuth (`grok`) or API-key (`grok-api`) lanes, and a fail-closed CLI video target: set `ima2 defaults set video grok/grok-imagine-video-1.5`, or pass `--model grok/grok-imagine-video-1.5`. The Grok OAuth image/video call is described there as an undocumented xAI token path; `grok-api` with `XAI_API_KEY` is the documented API-key route. [ima2 README](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/README.md)

```bash
ima2 models --kind video --json
ima2 video "Slow dolly toward a paper boat; no dialogue; finish on a still frame" \
  --model grok/grok-imagine-video-1.5 --duration 5 --resolution 720p \
  --aspect-ratio 16:9 --json -o clip.mp4
ima2 video "Animate this frame with a slow lateral move" \
  --model grok/grok-imagine-video-1.5 --ref first-frame.png \
  --duration 5 --resolution 720p --json -o clip.mp4
```

The CLI's generate flags include `--duration`, `--resolution`, `--aspect-ratio`, `--model`, `--provider`, repeatable `--ref`, `--as-reference`, repeatable `--voice` (max 3), `--planner-model`, `--storyboard`, `--topic`, output and JSON flags. Zero refs selects text-to-video; one `--ref` defaults to first-frame image-to-video; one with `--as-reference` or 2–7 refs selects reference-to-video. The CLI checks **1–15 seconds**, caps `--ref` at **7**, and defaults to **480p**/`auto` when used directly. `ima2 video analyze <generated-file> --json` analyzes first/last frames. [ima2 video CLI](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/commands/video.ts), [CLI body and validation](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/lib/videoMcp.ts)

The local HTTP route is **`POST /api/video/generate`**, accepting JSON such as `{"provider":"grok-api","model":"grok-imagine-video-1.5","prompt":"…","duration":5,"resolution":"720p","aspectRatio":"16:9","sourceImage":"<base64 image bytes>"}` for image-to-video; omit `sourceImage` for text-to-video or use `referenceImages` for reference-to-video. The synchronous response is **SSE** (`planning`, `submitted`, `progress`, `done`/`error`); `done` includes a local filename/URL, which the CLI downloads to `-o`. The route also supports `async: true` with request-ID events. [ima2 video route](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/routes/video.ts), [CLI SSE handling](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/lib/videoMcp.ts), [ima2 README](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/README.md)

**Limit mismatches:** the route's `MAX_REF2V_REFERENCES` is **14**, but ima2's own CLI rejects more than **7** and xAI currently documents **7**. Also, `ima2 video extend` validates **1–15 seconds** while xAI documents **2–10 seconds** for the added segment. Use ≤7 references and xAI's extension range for dependable direct paths; reconcile these local limits before exposing them in vid2. [ima2 extend validation](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/commands/video.ts), [xAI extension range](https://docs.x.ai/developers/model-capabilities/video/extension), [ima2 route constant](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/lib/imageModels.ts), [ima2 CLI cap](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/lib/videoMcp.ts), [xAI cap](https://docs.x.ai/developers/model-capabilities/video/reference-to-video)

### Exactly how a generated clip enters a vid2 timeline

Vid2 already has a `generate` source with `kind: "video"`. Its ima2 adapter normalizes defaults to **5 s, 720p, 16:9, `grok/grok-imagine-video-1.5`**, then calls `ima2 video <prompt> --duration … --resolution … --aspect-ratio … --model … [--ref seedImage] -o <cache path>`. The `seedImage` path is resolved relative to `timeline.json`; its **file bytes** enter the cache key. The adapter probes the returned file and records duration, geometry, SHA-256, model and prompt provenance. [vid2 assets contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/assets.md), [ima2 adapter](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/assets/ima2.ts), [resolver](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/assets/resolve.ts)

```json
{
  "version": 1,
  "sources": {
    "boatClip": {
      "type": "generate", "provider": "ima2", "kind": "video",
      "prompt": "A paper boat drifts left to right; no dialogue; hold on the last frame",
      "options": {
        "model": "grok/grok-imagine-video-1.5",
        "durationS": 5, "resolution": "720p", "aspectRatio": "16:9",
        "seedImage": "assets/boat-first-frame.png"
      }
    }
  },
  "scenes": [{
    "id": "boat", "duration": "5s",
    "layers": [{"type": "media", "source": "boatClip", "fit": "cover", "start": "0s", "end": "5s", "volume": 0}]
  }]
}
```

Remove `seedImage` for text-to-video. `volume: 0` leaves the generated clip's audio out of vid2's mix; set a positive media-layer volume and QA its audio if the generated sound is wanted. This does **not** pass xAI's `generate_audio: false` upstream: the current vid2 adapter invokes ima2's CLI, whose generate flags do not include that control. [vid2 adapter](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/assets/ima2.ts), [ima2 CLI flags](https://github.com/lidge-ai/ima2-gen/blob/0b9c2c9ba1a3ddcc91eaf8d84c2df77b5fa7ccd0/bin/commands/video.ts), [xAI silent-video field](https://docs.x.ai/developers/model-capabilities/video/generation) `vid2 assets resolve timeline.json` materializes and caches the clip (or `vid2 render timeline.json --generate` does so), after which ordinary compile/render uses the cached local MP4. Run `vid2 validate`, `vid2 assets providers --json` to check Grok readiness, render a proxy, then `vid2 qa proxy.mp4 --timeline timeline.json` and inspect the resulting evidence. A generated source is replaced with a normal local `video` source during materialization; the media layer trims it and, if its authored span exceeds footage, holds the last frame. Therefore choose scene/layer duration to match the probed clip if an accidental freeze would be wrong. [vid2 asset flow](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/assets.md), [vid2 resolver](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/assets/resolve.ts), [media rendering](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/compile/layers/media.ts), [media audio](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/compile/audio-plan.ts)

## Implications for vid2-gen

1. **Add `vid2 review` over existing QA artifacts** — highest value because the current contact sheet, seam frames, waveform, spectrogram and checks already supply most of the evidence; add model critique with timestamped, schema-checked findings and uncertainty. [Current QA artifacts](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md)
2. **Add an adaptive motion strip and cut fallback** — use authored cuts first, PySceneDetect when the timeline is unavailable, and dense short strips around rapid changes so the reviewer sees motion and one-frame faults. [Current 0.5-FPS contact sheet](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/src/qa/artifacts.ts), [PySceneDetect CLI](https://www.scenedetect.com/docs/latest/cli.html)
3. **Expose two review adapters: native Gemini video and sampled-frame vision** — Gemini can handle timestamped MP4/audio directly; xAI/OpenAI/Claude can reuse labeled PNG batches within their different limits.
