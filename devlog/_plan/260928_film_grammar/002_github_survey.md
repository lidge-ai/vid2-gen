## Comparison baseline: vid2-gen

At [vid2-gen `13a0e45`](https://github.com/lidge-ai/vid2-gen/tree/13a0e45a067c009f08c071caa7acd56eec2f7c7e), the author writes a JSON timeline and uses an ffmpeg-native CLI for capture, generated media, frame-resolved kinetic/stage animation, transitions, synth/music/SFX, mastering, and MP4 output. `vid2 audio beats` infers a fixed BPM grid; `vid2 audio snap` helps place an authored cut. `vid2 preview --at` renders exact composition frames. `vid2 qa` already makes a contact sheet, scene start/mid/end frames and seam ±1-frame stills, waveform/spectrogram, and format, black, freeze, loudness, A/V sync, text-safe, and contrast checks. Its packaged skill says **validate → resolve → preview stills → proxy render → QA → fix → final render → QA**. These are substantial existing foundations. [README](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/README.md) · [QA contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md) · [audio skill](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/skills/vid2-audio/SKILL.md) · [CLI skill](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/skills/vid2-cli/SKILL.md)

The gaps below are relative to that baseline: no native transcript/word-timed subtitle or speech-based EDL workflow is documented; no source-footage shot index or reference-video style analyzer is documented; and `qa` measures technical defects but does not itself ask a vision model or independent critic whether the rendered story, crop, cut, or typography works. The agent can consume still artifacts through an image-capable tool, but the CLI does not make that semantic review automatic. This is an inference from the published [command inventory](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/README.md), [QA contract](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md), and [timeline schema](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/schema/timeline.v1.json), rather than a claim that an external agent could never build those steps around vid2.

## Who actually closes a self-review loop?

**Strict test used here:** inspect pixels/audio from a *rendered output*, record a concrete finding, change the recipe/timeline/source, and render again. A still preview, format QA, or an EDL warning alone is not enough. A skill that instructs an agent to do this is identified separately from code that automatically executes the loop.

## Implications for vid2-gen

Ranked for an ffmpeg-native CLI whose authoring agent cannot directly watch or listen to the finished MP4. These are design recommendations inferred from the cited projects, not claims that their implementations can be copied without integration work.

1. **Cut-centered review bundle:** extend `vid2 qa` with a JSON manifest and per-cut **±1.5 s** filmstrip, waveform, caption labels and exact source/output frame IDs; let image-capable agents inspect one focused artifact and issue timecoded fixes. [video-use loop](https://github.com/browser-use/video-use/blob/b877063835e6ea6e457124da7e28a0ae26691dc3/SKILL.md) · [vid2 QA](https://github.com/lidge-ai/vid2-gen/blob/13a0e45a067c009f08c071caa7acd56eec2f7c7e/structure/qa.md)
2. **Optional semantic critic with honest status:** add a separate, opt-in `vid2 review --vision` consuming QA-selected frames and the brief/storyboard, returning `{timecode, frame, issue, evidence, suggestedTimelineField, confidence}`; bound revision attempts (for example **3**) and report `SKIPPED` when no VLM is configured. This closes the “technical QA passed, story failed” gap without silently sending media to a provider. [open-video judge/skip semantics](https://github.com/open-video-ai/open-video/blob/f72b0d716f41b07cdf551b24ca7313060ad175e5/core/judge.py) · [video-use three-pass cap](https://github.com/browser-use/video-use/blob/b877063835e6ea6e457124da7e28a0ae26691dc3/SKILL.md)
3. **Source-shot index before authoring:** `vid2 analyze shots footage.mp4` should emit scene boundaries, thumbnails, frame-addressed ranges and optional motion/exposure/subject scores; give the agent coarse-to-fine visual search rather than asking it to guess in/out points. [PySceneDetect CLI](https://www.scenedetect.com/cli/) · [video-agent `detect`](https://github.com/agamm/video-agent/blob/cc00d2815869cbf2d708426a5082612f0c3b4dbf/README.md) · [mimic `index_footage`](https://github.com/pouyashahrdami/mimic-mcp/blob/9dca836c78ac06d0a244364d878d7c9dfb44ca16/README.md)
4. **Transcript and caption sidecar:** accept source-word timing, confidence and speaker in JSON; map source words through cuts onto output time, then render karaoke/word/chunk caption presets and verify by re-transcribing the final render. Keep missing alignments explicit. [WhisperX](https://github.com/m-bain/whisperX/blob/771b4a14a9486f8fd5aef18ef49e35d639523dd3/README.md) · [Remotion caption schema](https://github.com/remotion-dev/remotion/blob/6f4e0d57d41a22fa60b1a9aa77e2b7d1d2adc210/packages/codex-plugin/skills/remotion-captions/SKILL.md) · [video-agent verification](https://github.com/agamm/video-agent/blob/cc00d2815869cbf2d708426a5082612f0c3b4dbf/.claude/skills/edl-edit/SKILL.md)
5. **Rhythm-aware rough cut and output beat audit:** supplement the existing fixed BPM grid with onset/energy/phrase data, shot scores, a controllable cut density (`beatStride`), and a **rendered-output** transient/cut offset report in frames. This would help choose footage to match music and catch encoder/mix latency, rather than merely quantizing authored time. [beat-synced-edit flags](https://github.com/ZiadAbdelkarim/beat-synced-edit/blob/48c09c92ee69c2d89b7e44b146bbd7b9c26fff08/README.md) · [librosa tracker](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html) · [video-shotcraft beat QA](https://github.com/Vincentwei1021/video-shotcraft/blob/e2d8928c57ef84701f9b0119ca4a1c28a62050c1/references/final-review.md)
6. **Reference-video grammar extraction:** produce a diffable style spec of shot lengths, transition types/durations, camera movement, caption geometry and audio hits; compare a vid2 render to the reference at matched moments, with paired frames and actionable timeline fields. This turns “make it like this” into inspectable evidence. [mimic analysis/review](https://github.com/pouyashahrdami/mimic-mcp/blob/9dca836c78ac06d0a244364d878d7c9dfb44ca16/README.md) · [video-shotcraft shot cards](https://github.com/Vincentwei1021/video-shotcraft/blob/e2d8928c57ef84701f9b0119ca4a1c28a62050c1/README.md)
7. **Editorial EDL fields:** support optional per-cut `rationale`, audio lead/lag for J/L cuts, alternate video source over continuous audio, and automatic silence/motion rough-cut suggestions. These are concrete film-grammar primitives missing from a scene-only edit. [video-agent EDL schema](https://github.com/agamm/video-agent/blob/cc00d2815869cbf2d708426a5082612f0c3b4dbf/.claude/skills/edl-edit/SKILL.md) · [Auto-Editor](https://github.com/WyattBlue/auto-editor/blob/7796222139b5d87fe32247f8a60a931b02006db5/README.md)
8. **Thin MCP and visual-client adapter:** expose existing `schema`, `validate`, `preview`, `render`, `qa`, and frame evidence as typed MCP tools with job IDs/status and image outputs; keep the CLI/JSON contract as source of truth. This helps agents whose host cannot conveniently open local paths, without changing vid2's renderer. [ffmpeg-mcp tools](https://github.com/video-creator/ffmpeg-mcp/blob/c2a9ab70fc82cc0b27dd31280968217f63036265/README.md) · [Remotion MCP App inline player](https://github.com/mcp-use/remotion-mcp-app/blob/84815888157a0403768b79a911563874d1aa014d/README.md)
